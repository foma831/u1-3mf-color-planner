# Руководство пользователя U1 3MF Color Planner

Приложение анализирует проектный 3MF из Bambu Studio/Orca, строит план печати для Snapmaker U1 и, при необходимости, Bambu Lab A1 mini, а затем создаёт отдельные неслайсенные проектные 3MF для каждого принтера и физической загрузки филамента.

Интерфейс приложения и создаваемые машинные отчёты — на английском. Это руководство — на русском.

## 1. Поддерживаемая конфигурация

- macOS на Apple Silicon;
- Snapmaker Orca 2.3.5 для файлов Snapmaker U1;
- Bambu Studio 02.02.00.85 для файлов Bambu Lab A1 mini;
- Snapmaker U1: четыре сопла 0,4 мм, CMY постоянно в T1–T3, сменная катушка в T4;
- Bambu Lab A1 mini: одно сопло 0,4 мм, одна внешняя катушка, без AMS Lite.

Writer-адаптеры проверяют точную версию приложения, исполняемый файл и профильный пакет. Другая версия Orca/Bambu Studio может открыть полученный файл, но приложение не разрешит production conversion, пока эта версия отдельно не квалифицирована.

Текущая `.app`-сборка имеет локальную ad-hoc подпись. Она предназначена для запуска на компьютере, где была собрана. Для внешней раздачи требуется Developer ID, notarization и stapling.

## 2. Как запустить актуальное приложение

Из корня проекта:

```sh
export PATH="/Users/evgeny/.rustup/toolchains/stable-aarch64-apple-darwin/bin:/opt/homebrew/bin:$PATH"
npm install
npm run build
open "target/release/bundle/macos/U1 3MF Color Planner.app"
```

Готовые локальные артефакты после сборки находятся здесь:

```text
target/release/bundle/macos/U1 3MF Color Planner.app
target/release/bundle/dmg/U1 3MF Color Planner_0.1.0_aarch64.dmg
```

Для режима разработки:

```sh
npm run dev
```

Не запускайте старую копию приложения из другой папки. Перед проверкой новой версии закройте прежнее окно и откройте `.app` из указанного каталога сборки.

## 3. Первый запуск: библиотека филаментов

Откройте вкладку **Filament Library** до анализа проекта.

Для пользовательской катушки обязательны:

- **Spool name**;
- **Color name**;
- **HEX color** строго в формате `#RRGGBB`, например `#010101`;
- **Material**: PLA или PETG.

Поля SKU, slicer profile, vendor, product line, optical descriptor, температурный диапазон, batch/lot, calibration reference и notes необязательны. Профиль слайсера остаётся авторитетным для температуры и процесса печати.

Статусы катушки:

- **In stock** — катушка участвует в планировании и доступна в селекторах;
- **Out of stock** — запись сохраняется, но исключается из всех вариантов CMY+X, Direct Spools, T4 и A1 mini.

Встроенные CMY и базовые катушки нельзя удалить или переименовать: их можно пометить **Out of stock**. Пользовательскую катушку можно редактировать или удалить. Удаление окончательное и делает старые назначения недействительными.

После добавления, редактирования, удаления или смены наличия вернитесь в **Print Plan** и выполните **Recalculate plan** или **Validate Choices**.

Каталог и калибровки хранятся локально в application data:

```text
filament-library-v2.json
cmyx-calibration-library-v2.json
```

В интерфейсе пока нет import/export этих библиотек. Перед удалением application data сделайте резервную копию файлов вручную.

## 4. Анализ 3MF и чтение плана

1. Нажмите **Choose 3MF**.
2. Выберите исходный проект.
3. Нажмите **Analyze Project**.
4. Проверьте исключённые альтернативные платы/детали.
5. В таблице изучите для каждой целевой платы:
   - количество исходных цветов;
   - количество effective material-color pairs;
   - выбранную стратегию;
   - фактический loadout;
   - качество цвета и Delta E;
   - действие перед следующим заданием;
   - раскрываемые warnings.

**Error** блокирует конвертацию. **Warning/Review** требует проверки и иногда отдельного подтверждения, но не всегда блокирует. **Resolve errors** означает, что для этой строки ещё нет допустимого физического назначения, подтверждения замены или adapter contract.

Количество видимых цветов и количество effective pairs могут отличаться. Одинаковый HEX остаётся отдельной парой, если отличается материал или исходный профиль.

## 5. CMY+X или Direct Spools

### CMY+X Full Spectrum

T1–T3 остаются Cyan, Magenta и Yellow. T4 содержит Grey, White, Black или другую запланированную катушку. Программа строит nominal-рецепты смешивания и группирует платы так, чтобы в одном U1 job использовалось не более четырёх физических катушек.

Если точный цвет получить нельзя, интерфейс показывает ближайший вариант, прогнозный цвет, Delta E, рецепт и требуемый T4. Можно подтвердить именно этот fingerprint-bound вариант либо добавить подходящую физическую катушку.

### Direct Spools

Direct Spools доступен, когда выбранной области требуется не более четырёх
physical Direct identities. Semantic-пары по-прежнему различают material,
role, RGB и source profile, поэтому остаются отдельными строками CMY+X и
отдельными решениями пользователя. Но различие только в роли не занимает
вторую катушку, если material, RGB и явно объявленный source profile полностью
совпадают: такие строки используют одну physical identity, spool и toolhead.
При неизвестном profile программа консервативно не делает такого объединения.
Интерфейс показывает оба числа и объясняет, сколько semantic-пар требуют
сколько физических позиций из четырёх.

Для отдельной существующей области это не запрещает объединить цвета намеренно:

1. выберите **Direct Spools**;
2. для каждой исходной строки выберите катушку из **Selected spool**;
3. назначьте одну и ту же катушку всем исходным цветам, которые хотите объединить;
4. приложение автоматически выровняет их на один toolhead и покажет **Combined source colors**;
5. если позже снова назначить одной из объединённых физических позиций отдельную
   катушку, приложение автоматически перенесёт её на первую свободную T1–T4;
6. если меняется PLA/PETG, отдельно подтвердите mechanical-property risk;
7. нажмите **Recalculate plan**.

Пример прежнего случая F10 + F6: выберите одну и ту же Creality PETG в обеих строках F10 и F6. Первое назначение больше не должно сбрасываться; обе строки становятся одним физическим цветом, после чего плата может стать single-spool candidate.

### Direct Spools для всего проекта

Если всем включённым source scopes проекта вместе требуется не более четырёх
physical Direct identities, появляется блок **Project-wide Direct Spools**.
Он применяет одну согласованную палитру ко всему включённому проекту. Material,
role, RGB и source profile сохраняются в semantic identity и не теряются в
строках сравнения. Role-only строки с одинаковыми material, RGB и явно
объявленным source profile автоматически связаны одной физической позицией;
unknown profile остаётся отдельным.

Для каждой пары блок одновременно показывает:

- **Original project pair** — исходный swatch, HEX, материал, роль, source slot/profile и где пара используется;
- **Current CMY+X** — текущий рецепт, прогнозный swatch, HEX, Delta E и confidence;
- **Physical spool at print time** — фактическую катушку из позиций **In stock**, её swatch, HEX и назначенный T1–T4;
- **Varies by scope** и отдельные строки по scopes, если один и тот же исходный цвет сейчас имеет разные CMY+X-результаты в разных частях проекта.

Порядок работы:

1. выберите физическую катушку для каждой исходной пары;
2. для намеренного объединения назначьте одну и ту же катушку нескольким парам — она останется на одном общем toolhead;
3. отдельно подтвердите mechanical-property risk для каждой пары, где меняется материал;
4. нажмите **Apply project-wide palette**;
5. нажмите **Recalculate Plan**: только backend-пересчёт подтверждает допустимость assignments, batches и setup actions.

Если unique physical Direct identities больше четырёх, блок показывает число
semantic-пар, число физических позиций и точную причину недоступности, а кнопка
применения не отображается. Текущая версия работает с уже существующими
included source scopes и всем проектом; произвольные группы объектов,
создаваемые пользователем, пока не реализованы.

## 6. Как назначить A1 mini

1. В нижней панели включите **Use Bambu Lab A1 mini for eligible mono parts**.
2. Нажмите появившуюся кнопку **Recalculate plan**.
3. Выберите нужную плату в таблице.
4. В **Prepare this plate for** выберите **Auto**, **Snapmaker U1** или **Bambu Lab A1 mini**.
5. Снова пересчитайте план.

A1 mini требует итог ровно из одной физической катушки. Исходник может содержать несколько цветов, если вы сначала объединили все его mappings в одну и ту же катушку через Direct Spools. После пересчёта станет доступен выбор A1 mini.

Отдельно проверяются:

- размещение в объёме 180 × 180 × 180 мм;
- материал и A1 mini profile;
- один logical filament slot;
- отсутствие AMS/filament switcher.

При невозможности A1 mini интерфейс оставляет объект на U1 и показывает причину: несколько физических катушек, геометрия, неподдерживаемый материал/профиль или отсутствующая отдельная spool identity.

## 7. Проверка и настоящая конвертация

**Export JSON Plan** сохраняет только JSON-отчёт. Эта кнопка не создаёт 3MF.

Для создания проектов:

1. устраните blocking errors;
2. нажмите **Validate Choices** или **Recalculate plan** после любых изменений;
3. убедитесь, что все требуемые adapter checks имеют статус Available/Qualified;
4. нажмите **Approve & Convert**;
5. выберите родительскую папку назначения;
6. в preflight проверьте каждый output, loadout, setup actions, exclusions и warnings;
7. подтвердите требуемые предупреждения;
8. нажмите **Convert projects**.

Исходный 3MF не перезаписывается. Приложение создаёт новую папку и не заменяет уже существующий bundle с тем же именем.

## 8. Что находится в результате

```text
<source>__converted/
  u1-full-spectrum/*.3mf
  u1-direct/*.3mf
  a1-mini/*.3mf
  manifest.json
  conversion-plan.json
  conversion-report.html
  checksums.sha256
```

- U1 Full Spectrum: один неслайсенный 3MF на физический batch/loadout; внутри может быть несколько plates.
- U1 Direct: один неслайсенный 3MF на Direct batch.
- A1 mini: один неслайсенный 3MF на target plate.
- `manifest.json`: точная связь source → job/plate, катушки, профили и проверки.
- `conversion-plan.json`: утверждённый канонический план.
- `conversion-report.html`: читаемый offline-отчёт.
- `checksums.sha256`: контрольные суммы всех файлов.

Откройте U1-файлы в Snapmaker Orca, A1-файлы — в Bambu Studio. Перед slice проверьте printer, nozzle, plate, profile, T1–T4 или внешнюю A1-катушку. Затем выполните slice в целевом слайсере.

A1-файлы не группируются только потому, что используют одну и ту же катушку:
writer создаёт один отдельный неслайсенный 3MF для каждой целевой A1 mini
plate. Несколько объектов могут находиться внутри одной такой target plate,
если именно так их сформировал и проверил планировщик.

## 9. Смена катушек и Print Run

Приложение не управляет принтером и не вставляет pause для смены катушки. U1 не будет ждать оператора посреди печати.

Каждая смена выполняется только:

1. после завершения предыдущего отдельного print job;
2. до запуска следующего job.

После успешной конвертации откройте **Print Run**. Он показывает блокирующие checkpoints:

- загрузить/заменить T4;
- выполнить полный Direct setup T1–T4;
- подтвердить одну внешнюю катушку A1 mini;
- после Direct batch вернуть CMY, если включён **Restore CMY setup**.

Отметьте завершение платы, физически выполните указанную смену, подтвердите checkpoint и только затем переходите к следующему заданию.

## 10. Калибровка CMY+X

Купленная «откалиброванная» катушка сама по себе не калибрует смешивание на конкретном U1. Результат зависит от точных T1–T4 spool identities, партии, процесса, ориентации и геометрии coupon.

Рабочий процесс:

1. откройте **Color Calibration**;
2. выберите точную T4-катушку и geometry preset;
3. сгенерируйте рекомендованный 18-swatch calibration candidate;
4. откройте его в Snapmaker Orca, проверьте и slice;
5. напечатайте chart точным CMY+T4 loadout;
6. измерьте каждый нужный swatch или сравните его при контролируемом освещении;
7. внесите recipe, measured `#RRGGBB`, дату, метод и подтверждение физического swatch;
8. пересчитайте основной проект.

Instrument Lab/sRGB даёт более надёжные данные; visual comparison сохраняется как низкоуверенное свидетельство. Legacy/nominal записи видимы, но не используются как measured calibration.

Black или White можно применять как прямой solid T4 без mix calibration. Физически точный смешанный рецепт с ними требует измерения в этом точном контексте. Без него результат остаётся nominal approximation и требует явного одобрения.

## 11. Если конвертация заблокирована

Проверьте по порядку:

1. все используемые катушки имеют **In stock**;
2. HEX имеет формат `#RRGGBB`;
3. после изменений выполнен Recalculate/Validate;
4. все Direct mappings назначены;
5. many-to-one действительно использует одну и ту же катушку;
6. material substitution подтверждён отдельно;
7. для A1 mini результат содержит одну физическую катушку и проходит 180 мм packing;
8. установлены точные квалифицированные версии Orca/Bambu Studio;
9. все обязательные warnings/approvals подтверждены;
10. выбранная output directory существует, а итоговой bundle-папки ещё нет.

Если сохранённый Print Run восстанавливается после перезапуска, frontend-запись
используется только как недоверенная подсказка, где искать bundle. Право на
восстановление даёт отдельная backend-private запись из application-data
`publication-receipts-v1`. Она связывает версию сборки, канонический путь,
размер и SHA-256 исходника, fingerprint плана, hash canonical preflight,
выходной путь и identity каталога, а также пути, размеры и SHA-256 всех 3MF и
metadata-файлов.

Backend повторно проверяет source, план, output identity, каждый project 3MF,
manifest, report и checksums. Восстановление работает fail-closed: отсутствие,
устаревание или несовпадение private receipt, перенос/подмена каталога либо
изменение любого файла блокирует Print Run. Поскольку converter никогда не
перезаписывает существующий output path, для повторной конвертации выберите
другую родительскую папку либо сначала переместите/удалите старый недоверенный
bundle.

Сам checksummed bundle можно скопировать и открыть в целевом слайсере, но
автоматическое восстановление Print Run намеренно привязано к исходному месту
публикации и identity каталога.
