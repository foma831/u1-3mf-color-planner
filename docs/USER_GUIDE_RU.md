# Руководство пользователя U1 3MF Color Planner

Приложение анализирует проектный 3MF из Bambu Studio/Orca, строит план печати для Snapmaker U1 и, при необходимости, Bambu Lab A1 mini, а затем создаёт отдельные неслайсенные проектные 3MF для каждого принтера и физической загрузки филамента.

Интерфейс приложения и создаваемые машинные отчёты — на английском. Это руководство — на русском.

## 1. Поддерживаемая конфигурация

- macOS на Apple Silicon;
- Snapmaker Orca 2.3.6 для файлов Snapmaker U1;
- Bambu Studio 02.02.00.85 для файлов Bambu Lab A1 mini;
- основной принтер Snapmaker U1: четыре сопла 0,4 мм, CMY постоянно в T1–T3,
  сменная катушка в T4;
- опциональный второй принтер Bambu Lab A1 mini: одно сопло 0,4 мм, одна внешняя
  катушка, без AMS Lite.

Writer-адаптеры проверяют точную версию приложения, исполняемый файл и профильный пакет. Другая версия Orca/Bambu Studio может открыть полученный файл, но приложение не разрешит production conversion, пока эта версия отдельно не квалифицирована.

Текущая `.app`-сборка имеет локальную ad-hoc подпись. Она предназначена для запуска на компьютере, где была собрана. Для внешней раздачи требуется Developer ID, notarization и stapling.

## 2. Как запустить актуальное приложение

Из корня проекта:

```sh
npm install
npm run build
open "target/release/bundle/macos/U1 3MF Color Planner.app"
```

Команды проекта сами находят активный Cargo через `rustup`, включая установку
Homebrew, даже если каталог Cargo отсутствует в `PATH` текущего терминала.

Готовые локальные артефакты после сборки находятся здесь:

```text
target/release/bundle/macos/U1 3MF Color Planner.app
target/release/bundle/dmg/U1 3MF Color Planner_0.1.0_aarch64.dmg
```

Для режима разработки:

```sh
npm run dev
```

Не запускайте старую копию приложения из другой папки. Перед проверкой новой версии закройте прежнее окно и откройте `.app` из указанного каталога сборки.

## 3. Первый запуск: катушки и Project setup

Стартовый экран **Print Plan** ведёт по четырём последовательным шагам. Следующий
шаг становится активным только после подтверждения предыдущего, поэтому искать
скрытые настройки в нижней панели не требуется.

### Step 1 — подтверждение физических катушек

Откройте **Filament Library** кнопкой **Confirm inventory** и отметьте
**Available now** только для катушек, которые физически доступны сейчас. После
этого вернитесь в **Print Plan**: **Step 1** получит отметку о завершении, а
**Step 2** раскроет видимую карточку **Project setup**.

При первом нативном запуске встроенные записи намеренно имеют статус
**Not available**. Они являются каталогом возможных материалов, а не заявлением о
том, что эти катушки физически лежат рядом с принтером. Отметьте **Available now**
только для катушек, которые действительно есть в наличии.

Для пользовательской катушки обязательны:

- **Spool name**;
- **Color name**;
- **HEX color** строго в формате `#RRGGBB`, например `#010101`;
- **Material**: PLA, PETG или PVA.

Для PVA поле **Profile** обязательно. Для катушки Reli3D из текущей
конфигурации выберите **Reli3D PVA @U1**. Этот профиль не подменяется профилем
Snapmaker и задаёт собственные ограничения температуры, расхода и ретракта.

Поля SKU, slicer profile, vendor, product line, optical descriptor, температурный
диапазон, batch/lot, calibration reference и notes находятся в раскрываемом блоке
**Advanced traceability & calibration** и необязательны. Профиль слайсера остаётся
авторитетным для температуры и процесса печати.

Статусы катушки:

- **Available now** — катушка участвует в планировании и доступна в селекторах;
- **Not available** — запись сохраняется, но исключается из всех вариантов CMY+X, Direct Spools, T4 и A1 mini.

Встроенные CMY и базовые катушки нельзя удалить или переименовать: их можно пометить
**Not available**. Пользовательскую катушку можно редактировать или удалить.
Удаление окончательное и делает старые назначения недействительными.

После добавления, редактирования, удаления или смены наличия вернитесь в
**Print Plan**. Для уже проанализированного проекта выполните **Recalculate
plan**.

### Step 2 — выбор способа печати текущего проекта

В карточке **Project setup** сразу выберите независимые параметры проекта.

**Printers for this project**:

- **Snapmaker U1 only** — все допустимые задания остаются на U1;
- **Snapmaker U1 + Bambu Lab A1 mini** — первый же анализ проверяет A1 mini и
  назначает туда только подходящие однофиламентные задания.

**U1 printing method**:

- **Automatic** — рекомендуемый вариант: планировщик сравнивает CMY+X и Direct
  Spools отдельно для каждой области проекта;
- **Direct Spools only** — строгий запрос на реальные катушки. Программа не
  переключится на CMY+X молча; область с более чем четырьмя effective physical
  identities или без допустимого назначения останется с понятной блокирующей
  причиной. При dedicated PVA одна из четырёх позиций уже занята поддержкой;
- **CMY+X Full Spectrum only** — первый план использует постоянные C/M/Y и
  планируемую катушку T4, не выбирая Direct Spools.

**U1 plate layout**:

- **Preserve source plates** — безопасное значение по умолчанию: объекты из
  разных исходных плат не помещаются на одну целевую U1-плату;
- **Combine compatible source plates** — явное разрешение попробовать сократить
  число целевых U1-плат. Объединяются только задания с одинаковыми принтером,
  стратегией, material environment и process contract. Для Direct Spools
  частичные раскладки совместимы, если ни в одной позиции T1–T4 нет двух разных
  катушек: например, `White · Black · Empty · Red` может использовать общий
  loadout `White · Black · Yellow · Red`. Жёлтая катушка останется загруженной,
  но на первой группе деталей не будет использоваться. Fast mono сохраняется
  отдельно. Настройка работает и для Direct Spools, и для CMY+X Full Spectrum.

Даже при включённом объединении планировщик может оставить несколько плат: все
объекты вместе должны помещаться на платформе с учётом clearance, brim/skirt и
prime tower. Исходный 3MF при этом никогда не изменяется — repacking относится
только к создаваемым target plates. Эта настройка относится к U1; допустимые
однофиламентные задания A1 mini по-прежнему упаковываются по собственным
ограничениям принтера.

В блоке **Filament loaded now** укажите фактические катушки в **U1 T1**, **U1
T2**, **U1 T3**, **U1 T4** и, если A1 mini добавлен в оборудование, во внешней
позиции A1 mini. Этот блок виден для Automatic, CMY+X и Direct Spools: текущая
загрузка нужна планировщику при любом способе печати.

Одна физическая катушка не может одновременно находиться в двух позициях. Если
позиция неизвестна, оставьте **Unknown / not confirmed**: первый переход будет
рассчитан консервативно, без выдуманного состояния принтера. Выбранная раскладка
сохраняется отдельно от стратегии проекта, используется в самом первом анализе
и предлагается как исходное состояние следующего проекта. Нажмите **Confirm
project setup**.

В блоке **Support material** выберите **Use model material** либо **Dedicated
PVA on T4**. Второй вариант доступен, когда в Filament Library есть доступная
катушка PVA с выбранным квалифицированным профилем. Для показанной катушки
Reli3D выберите **Reli3D PVA @U1**; пустой профиль больше не подменяется
Snapmaker автоматически. В поле **PVA usage** оставьте **Contact interface
only (Recommended)**: тело поддержки печатается материалом модели, а только три
контактных слоя — PVA. **Entire support** используйте лишь для недоступных
полостей после отдельной проверки адгезии и сушки. Планировщик зарезервирует T4
и ограничит модель тремя остальными физическими катушками. Обычные Direct Spool
controls не могут переназначить выделенную PVA с T4.

### Проверка новой катушки PVA перед большой печатью

В репозитории есть маленький неслайсенный проект
`Sample/Results/Reli3D-PVA-diagnostic-U1-2.3.6.3mf`. Он использует только T4 и
профиль **Reli3D PVA @U1**; support и prime tower выключены. Купон проверяет:

- широкое основание — первый слой и сцепление со столом;
- четыре отдельные башни — вытекание, нити и ретракт;
- стенку 0,6 мм — стабильность малой подачи;
- мост 10 мм — температуру расплава и охлаждение.

Перед печатью откройте проект в Snapmaker Orca 2.3.6, проверьте **U1 (0.4
nozzle)**, **T4 = Reli3D PVA @U1**, выполните **Slice plate** и просмотрите весь
Preview. Проект задаёт 220 °C для первого слоя, 210 °C для остальных слоёв,
стол 60 °C, слой 0,20 мм и ограничение потока 3 мм³/с. Не отправляйте файл на
принтер, если Orca сообщает о ремонте геометрии, отсутствующем профиле или
назначает модель не на T4.

Напечатайте один и тот же файл два раза: сначала в текущем состоянии катушки,
затем после сушки по температуре и времени, указанным Reli3D на катушке или в
инструкции к материалу. Во время печати держите PVA в сухом боксе. Не назначайте
режим сушки только по общему совету для PVA: слишком высокая температура может
деформировать именно эту катушку.

Интерпретация результата:

- хаотичная тонкая паутина по всей детали, пузырьки, шипение, пар, пенистая или
  неоднородная поверхность, заметно исчезнувшие после сушки — влажный PVA;
- гладкая экструзия без шипения, но повторяемые прямые нити между башнями и
  наплывы на одинаковых местах — температура/ретракт;
- разрывы стенки, матовая недоэкструзия и слабые мосты — подача, частичное
  засорение, слишком низкая температура либо слишком высокий фактический поток;
- поднятые углы основания при ровной экструзии — загрязнение стола, первый слой
  или адгезия, а не сама сушка.

Для повторной генерации без перезаписи существующего файла:

```sh
cargo run -p u1-converter-cli --bin u1-converter -- build-pva-diagnostic \
  --output "/новый/путь/Reli3D-PVA-diagnostic-U1-2.3.6.3mf" \
  --orca-app "/Applications/Snapmaker Orca.app"
```

Snapmaker U1 всегда остаётся primary printer. Явный выбор U1+A1 подтверждает и
сохраняет наличие A1 mini. Выбор U1-only для конкретного проекта сам по себе не
означает, что A1 mini отсутствует физически, и не удаляет его из hardware-профиля.
Список оборудования можно изменить через шестерёнку в верхней панели →
**Application setup** → **Available printers** либо по ссылке **Change available
equipment** в **Project setup**.
Сохранённый hardware-профиль определяет, доступен ли A1 mini, а **Project setup**
отдельно определяет, используется ли он именно в текущем плане.

Выбранный project intent сохраняется как удобное значение по умолчанию, но для
каждого нового проекта **Step 2** всё равно остаётся видимым и требует явного
подтверждения. Поэтому A1 mini, Direct Spools или CMY+X не могут быть применены
незаметно.

### Step 3 — открытие и анализ 3MF

После подтверждения **Project setup** нажмите **Open 3MF** в **Step 3**, выберите
файл, затем нажмите **Analyze Project**. Кнопка анализа в заголовке также остаётся
доступной, но до подтверждения **Step 2** она показывает причину блокировки.

Hardware-профиль, фактическая раскладка принтеров и последний project intent сохраняются в локальном профиле
приложения. Каталог и калибровки хранятся локально в application data:

```text
filament-library-v3.json
cmyx-calibration-library-v2.json
```

В интерфейсе пока нет import/export этих библиотек. Перед удалением application data сделайте резервную копию файлов вручную.

## 4. Анализ 3MF и чтение плана

Первый анализ получает подтверждённый **Project setup** вместе с путём к 3MF.
Это означает, что выбранные принтеры и U1 printing method участвуют уже в первом
авторитетном плане: приложение не строит сначала скрытый U1/Auto-план и не делает
лишний промежуточный пересчёт.

Геометрия, цвета, материалы и физические ограничения по-прежнему определяются из
самого 3MF. Поэтому включённый A1 mini может получить ноль подходящих заданий, а
строгий Direct Spools может показать блокирующую несовместимость. В обоих случаях
интерфейс сохраняет и явно показывает исходный запрос пользователя отдельно от
результата планировщика.

1. Нажмите **Open 3MF**.
2. Выберите исходный проект.
3. Нажмите **Analyze Project**.
4. В верхней видимой карточке **Project setup** проверьте применённый запрос и
   фактический результат A1 mini.
5. Проверьте исключённые альтернативные платы/детали.
6. В компактной таблице изучите принтер, стратегию, физическую загрузку и статус.
   Кнопка **Show detailed columns** добавляет исходную палитру, объекты и setup action.
7. Раскройте **Advanced planning**, только если нужно изменить альтернативные платы
   или общую Direct-палитру.
8. Для выбранной строки проверьте в боковой панели:
   - количество исходных цветов;
   - количество effective material-color pairs;
   - выбранную стратегию;
   - фактический loadout;
   - качество цвета и Delta E;
   - действие перед следующим заданием;
   - раскрываемые warnings.

При включённом **Combine compatible source plates** одна строка U1 может
содержать объекты из нескольких исходных плат. Проверьте перечисленные source
scopes: связь каждого объекта с его исходной платой сохраняется в плане и
выходном manifest. Число target plates является результатом реального packing,
а не обещанным сокращением до одной платы.

**Error** блокирует конвертацию. **Warning/Review** требует проверки и иногда отдельного подтверждения, но не всегда блокирует. **Resolve errors** означает, что для этой строки ещё нет допустимого физического назначения, подтверждения замены или adapter contract.

Количество видимых цветов и количество effective pairs могут отличаться. Одинаковый HEX остаётся отдельной парой, если отличается материал или исходный профиль.

## 5. CMY+X или Direct Spools

Начальный выбор между CMY+X и Direct Spools делается в **Step 2** до анализа и
относится к текущему проекту, а не к hardware-профилю. После анализа можно
изменить глобальный выбор через постоянно видимую карточку **Project setup** или
уточнить стратегию отдельных допустимых scopes. Изменение показывает **Changes
pending** и требует **Apply & recalculate**.

### CMY+X Full Spectrum

T1–T3 остаются Cyan, Magenta и Yellow. T4 содержит Grey, White, Black или другую запланированную катушку. Программа строит nominal-рецепты смешивания и группирует платы так, чтобы в одном U1 job использовалось не более четырёх физических катушек.

Если точный цвет получить нельзя, интерфейс показывает ближайший вариант,
прогнозный цвет, Delta E, рецепт и требуемый T4. Кнопка **Change CMY color**
открывает палитру всех рецептов, которые backend считает физически допустимыми
для текущего loadout. Выбор доступен и в общей карточке цветового решения, и в
**Original source palette** выбранной платы; оба места изменяют одно и то же
сопоставление. Одинаковая semantic source identity получает тот же рецепт во
всех связанных scopes. После ручного выбора прежнее одобрение сбрасывается:
нужно подтвердить новый вариант и нажать **Recalculate plan**.

При PVA в T4 палитра модели содержит только рецепты T1–T3: варианты, использующие
T4, backend исключает. Поэтому ручной выбор не может незаметно включить PVA в
цвет модели. Можно подтвердить именно показанный fingerprint-bound вариант либо
добавить подходящую физическую катушку.

Для ознакомления со всем расчётным диапазоном откройте верхнеуровневую вкладку
**Color Reference**. Она доступна без загрузки 3MF и содержит две таблицы:

- **CMY** — 46 уникальных nominal-цветов из T1–T3;
- **CMYK Full Spectrum** — 135 теоретических nominal-цветов из T1–T4.

Строка показывает swatch, HEX, метод и Ratio/Cycle-рецепт; поиск принимает HEX,
обозначения C/M/Y/K, toolhead и название метода. Если Ratio и Cycle дают один
HEX, он показывается одной строкой с эквивалентным рецептом. CMYK-таблица не
разрешает обычному непрозрачному Black участвовать в production conversion:
это справочный расчёт для квалифицированного и откалиброванного компонента K.
Физический результат всё равно проверяется калибровочной печатью.

### Direct Spools

В обычном режиме Direct Spools доступен, когда выбранной области требуется не более четырёх
physical Direct identities. Semantic-пары по-прежнему различают material,
role, RGB и source profile, поэтому остаются отдельными строками CMY+X и
отдельными решениями пользователя. Но различие только в роли не занимает
вторую катушку, если material, RGB и явно объявленный source profile полностью
совпадают: такие строки используют одну physical identity, spool и toolhead.
При неизвестном profile программа консервативно не делает такого объединения.
Интерфейс показывает оба числа и объясняет, сколько semantic-пар требуют
сколько физических позиций из четырёх.

Для отдельной существующей области это не запрещает объединить цвета намеренно:

1. выберите **Direct Spools**;
2. для каждой исходной строки выберите катушку из **Selected spool**;
3. назначьте одну и ту же катушку всем исходным цветам, которые хотите объединить;
4. приложение автоматически выровняет их на один toolhead и покажет **Combined source colors**;
5. если позже снова назначить одной из объединённых физических позиций отдельную
   катушку, приложение автоматически перенесёт её на первую свободную T1–T4;
6. если меняется PLA/PETG, отдельно подтвердите mechanical-property risk;
7. нажмите **Recalculate plan**.

Пример прежнего случая F10 + F6: выберите одну и ту же Creality PETG в обеих строках F10 и F6. Первое назначение больше не должно сбрасываться; обе строки становятся одним физическим цветом, после чего плата может стать single-spool candidate.

### Custom four-spool palettes для отдельных плат

Если у платы больше четырёх исходных цветов, но вы готовы намеренно сократить
палитру и перезагружать все T1–T4 между заданиями:

1. выберите недоступную Direct-плату и в блоке **Strategy comparison** нажмите
   **Create 4-spool palette**;
2. программа сразу выполнит авторитетный пересчёт только для выбранного source
   scope, сохранит все исходные identities и предложит не более четырёх
   совместимых катушек со статусом **Available now**;
3. проверьте включённый вариант **Custom 4-Spool Direct** и все исходные строки;
4. в каждой строке **Selected spool** укажите фактическую катушку, которой нужно
   заменить исходный цвет; одну катушку разрешено назначить нескольким цветам;
5. подтвердите каждую замену PLA/PETG отдельно и снова пересчитайте план.

Если совместимых катушек недостаточно, рядом останутся видимые действия
**Review Filament Library** и повторной попытки. Программа не подменяет материал
автоматически. Проектный переключатель в **Advanced Direct settings** остаётся
дополнительным способом заранее включить такие палитры, но искать его для выхода
из недоступной Direct-платы больше не требуется.

Рядом с **Selected spool** отображается отдельный цветовой образец выбранной
катушки. Он обновляется сразу при смене значения и помогает различать катушки
с похожими названиями; точный HEX остаётся доступен в подсказке образца.

Например, семь исходных physical Direct identities остаются семью строками для
проверки, но должны ссылаться максимум на четыре уникальные катушки. Автоматический
вариант минимизирует суммарное цветовое отличие, не объединяет разные материалы
без подтверждения и учитывает уже загруженные катушки как дополнительный критерий.
Пятая уникальная катушка на одной плате не назначается: сначала объедините одну из
существующих строк с уже выбранной катушкой.

Ручное назначение исходной identity на первой плате автоматически переносится на
остальные ещё не редактировавшиеся scopes с той же material/color/profile identity.
Как только вы вручную исправили соответствующую строку другой платы, это решение
становится локальным и последующие изменения первой платы его не перезаписывают.
Наследование сбрасывается при анализе нового проекта.

Каждый конфликтующий набор катушек является отдельной setup boundary. Для Direct
Spools планировщик сначала объединяет совместимые частичные loadouts в общий
супернабор, затем упаковывает их объекты и показывает полные `Unload`/`Load` для
T1–T4. Если все строки платы свести к одной совместимой катушке,
после пересчёта она может стать кандидатом для A1 mini.

Порядок U1-партий рассчитывается по фактическим итоговым T1–T4, а не только по
названию стратегии или исходному цвету. На каждом шаге планировщик выбирает
следующий совместимый batch с наименьшим числом физических перестановок относительно
текущего состояния. Одинаковые loadouts печатаются подряд одной партией. Если для
Direct включён возврат CMY, стоимость обязательного возврата тоже участвует в выборе.

### Массовое переключение U1-плат

Над таблицей **U1 Plates** находится блок **Bulk U1 strategy**. Он позволяет не
открывать каждую плату отдельно:

1. включите **Select all U1 plates** либо отметьте только нужные строки в колонке
   **Bulk**;
2. при необходимости используйте **Select Direct-compatible**, чтобы выбрать
   только уже допустимые Direct scopes;
3. нажмите **Set selected to Direct Spools** или **Set selected to CMY+X**;
4. нажмите **Recalculate plan**, затем назначьте или проверьте реальные катушки.

Выбор применяется к source scope. Если одна исходная область была разбита на
несколько целевых плат, их флажки связаны и стратегия меняется согласованно.
Если хотя бы один выбранный scope пока недоступен для Direct, кнопка Direct
блокируется и показывает причину. Для палитры из более чем четырёх исходных
identities откройте этот scope, нажмите **Create 4-spool palette** и проверьте
предложенное соответствие либо исключите scope из массового выбора.

### Direct Spools для всего проекта

Если всем включённым source scopes проекта вместе требуется не более четырёх
physical Direct identities, появляется блок **Project-wide Direct Spools**.
Он применяет одну согласованную палитру ко всему включённому проекту. Material,
role, RGB и source profile сохраняются в semantic identity и не теряются в
строках сравнения. Role-only строки с одинаковыми material, RGB и явно
объявленным source profile автоматически связаны одной физической позицией;
unknown profile остаётся отдельным.

Для каждой пары блок одновременно показывает:

- **Original project pair** — исходный swatch, HEX, материал, роль, source slot/profile и где пара используется;
- **Current CMY+X** — текущий рецепт, прогнозный swatch, HEX, Delta E и confidence;
- **Physical spool at print time** — фактическую катушку из позиций **Available now**, её swatch, HEX и назначенный T1–T4;
- **Varies by scope** и отдельные строки по scopes, если один и тот же исходный цвет сейчас имеет разные CMY+X-результаты в разных частях проекта.

Порядок работы:

1. выберите физическую катушку для каждой исходной пары;
2. для намеренного объединения назначьте одну и ту же катушку нескольким парам — она останется на одном общем toolhead;
3. отдельно подтвердите mechanical-property risk для каждой пары, где меняется материал;
4. нажмите **Apply project-wide palette**;
5. нажмите **Recalculate plan**: только backend-пересчёт подтверждает допустимость assignments, batches и setup actions.

Если unique physical Direct identities больше четырёх, project-wide блок показывает число
semantic-пар, число физических позиций и точную причину недоступности, а кнопка
применения не отображается. Это не запрещает описанный выше opt-in режим
**Custom 4-Spool Direct** для отдельных плат. Текущая версия работает с уже существующими
included source scopes и всем проектом; произвольные группы объектов,
создаваемые пользователем, пока не реализованы.

## 6. Как использовать A1 mini

Чтобы A1 mini учитывался уже в первом плане, в **Step 2** выберите **Snapmaker U1
+ Bambu Lab A1 mini**. Если этот вариант недоступен, нажмите **Add A1 mini** и
добавьте принтер в **Available equipment**, затем вернитесь к **Project setup**.

После **Analyze Project** карточка **Project setup** показывает запрос отдельно от
результата, например **A1 mini requested · 0 eligible plates**. Ноль не означает,
что выбор потерян: в этом проекте планировщик не нашёл mono-заданий, одновременно
проходящих ограничения размера, материала и физической катушки.

Чтобы изменить решение после анализа:

1. Нажмите **Change setup** в верхней карточке **Project setup**.
2. Выберите **Snapmaker U1 only** или **Snapmaker U1 + Bambu Lab A1 mini**.
3. В блоке **Filament loaded now** проверьте **A1 mini external spool**.
4. Нажмите **Apply & recalculate**.
5. Для точечной корректировки выберите плату в таблице и в **Prepare this plate
   for** укажите **Auto**, **Snapmaker U1** или **Bambu Lab A1 mini**, затем снова
   пересчитайте план.

В конфигурации доступного оборудования U1-only вариант U1+A1 заблокирован с
видимым объяснением; скрытого переключателя в нижней панели больше нет.

A1 mini требует итог ровно из одной физической катушки. Исходник может содержать несколько цветов, если вы сначала объединили все его mappings в одну и ту же катушку через Direct Spools. После пересчёта станет доступен выбор A1 mini.

Текущая катушка A1 mini задаёт только первый переход и не ограничивает цвета
следующих плат. Разные моно-платы разрешено назначать на разные катушки. Планировщик
сгруппирует платы с одинаковой катушкой, начнёт с уже установленной катушки, если она
нужна, и добавит явные `Unload`/`Load` перед каждым переходом к следующему цвету.
Если текущее состояние неизвестно, первая загрузка считается консервативной сменой.

Одна физическая катушка может последовательно использоваться и на U1, и на A1 mini.
В таком случае все U1-задания идут раньше A1-заданий, а инструкция требует перенести
катушку между принтерами. Такие задания нельзя запускать параллельно, если второй
экземпляр той же катушки отсутствует.

Отдельно проверяются:

- размещение в объёме 180 × 180 × 180 мм;
- материал и A1 mini profile;
- один logical filament slot;
- отсутствие AMS/filament switcher.

При невозможности A1 mini интерфейс оставляет объект на U1 и показывает причину:
несколько итоговых физических катушек в одном задании, геометрия, неподдерживаемый
материал/профиль или катушка со статусом **Not available**.

## 7. Проверка и настоящая конвертация

**Export JSON plan** находится в меню **More actions** и сохраняет только JSON-отчёт.
Эта кнопка не создаёт 3MF.

Для создания проектов:

1. устраните blocking errors;
2. нажмите **Validate plan** или **Recalculate plan** после любых изменений;
3. убедитесь, что все требуемые adapter checks имеют статус Available/Qualified;
4. нажмите **Review conversion…**;
5. выберите родительскую папку назначения;
6. в preflight проверьте каждый output, loadout, setup actions, exclusions и warnings;
7. подтвердите требуемые предупреждения;
8. нажмите **Convert projects**.

Исходный 3MF не перезаписывается. Приложение создаёт новую папку и не заменяет уже существующий bundle с тем же именем.

Если в исходном проекте включены автоматические поддержки `normal(auto)` или
`tree(auto)`, конвертер переносит их вместе с пороговым углом и ограничением
**On build plate only**. Платы при этом могут оставаться объединёнными: Snapmaker Orca
пересчитывает поддержки уже для общей целевой платы, а prime tower создаётся одна на
плату. Предупреждение Orca о floating regions может оставаться информационным; перед
печатью проверьте в Preview, что присутствуют слои **Support** и **Support interface**.
Неизвестный режим поддержки или неподдерживаемая объектная настройка не игнорируется —
export будет остановлен с объяснением.

## 8. Что находится в результате

```text
<source>__converted/
  u1-full-spectrum/*.3mf
  u1-direct/*.3mf
  a1-mini/*.3mf
  manifest.json
  conversion-plan.json
  conversion-report.html
  PRINT-INSTRUCTIONS.txt
  checksums.sha256
```

- U1 Full Spectrum: один неслайсенный 3MF на физический batch/loadout; внутри может быть несколько plates.
- U1 Direct: один неслайсенный 3MF на Direct batch.
- A1 mini: один неслайсенный 3MF на target plate.
- `manifest.json`: точная связь source → job/plate, катушки, профили и проверки.
- `conversion-plan.json`: утверждённый канонический план.
- `conversion-report.html`: читаемый offline-отчёт.
- `PRINT-INSTRUCTIONS.txt`: пошаговый порядок печати, целевой слайсер, платы,
  требуемые катушки и действия Load/Unload/Restore перед каждым заданием.
- `checksums.sha256`: контрольные суммы всех файлов.

Начинайте работу с `PRINT-INSTRUCTIONS.txt`: шаги в нём следуют фактическому
порядку опубликованных проектов. Все смены выполняются между заданиями, а не
посреди печати. Файл входит в `checksums.sha256` и повторную backend-проверку
опубликованного результата.

Откройте U1-файлы в Snapmaker Orca, A1-файлы — в Bambu Studio. Перед slice
проверьте printer, nozzle, каждую созданную target plate, размещение и
ориентацию объектов, profile, T1–T4 или внешнюю A1-катушку. Для cross-source
repacking это обязательная финальная визуальная проверка: manifest сохраняет
происхождение каждого объекта, но печатную раскладку всё равно должен
подтвердить оператор в целевом слайсере. Затем выполните slice.

A1-файлы не группируются только потому, что используют одну и ту же катушку:
writer создаёт один отдельный неслайсенный 3MF для каждой целевой A1 mini
plate. Несколько объектов могут находиться внутри одной такой target plate,
если именно так их сформировал и проверил планировщик.

## 9. Смена катушек и Print Run

Приложение не управляет принтером и не вставляет pause для смены катушки. U1 не будет ждать оператора посреди печати.

Каждая смена выполняется только:

1. после завершения предыдущего отдельного print job;
2. до запуска следующего job.

После успешной конвертации откройте **Print Run**. Он показывает блокирующие checkpoints:

- загрузить/заменить T4;
- выполнить полный Direct setup T1–T4;
- подтвердить требуемую внешнюю катушку A1 mini перед каждой её сменой;
- после Direct batch вернуть CMY, если включён **Restore CMY setup**.

Отметьте завершение платы, физически выполните указанную смену, подтвердите checkpoint и только затем переходите к следующему заданию.

Когда все платы и финальные checkpoints отмечены как выполненные, **Print Run**
показывает ожидаемую итоговую раскладку T1–T4 и A1 mini. Сверьте её с реальными
принтерами и нажмите **Use as current printer loadout**. Только это явное действие
обновляет исходное состояние следующего проекта. Одна конвертация раскладку не
сохраняет, потому что создание файлов физически не переставляет катушки.

## 10. Калибровка CMY+X

Купленная «откалиброванная» катушка сама по себе не калибрует смешивание на конкретном U1. Результат зависит от точных T1–T4 spool identities, партии, процесса, ориентации и геометрии coupon.

Рабочий процесс:

1. откройте **Color Calibration**;
2. выберите точную T4-катушку и geometry preset;
3. выберите `Full · 26 swatches` для полной калибровки либо
   `Quick · 10 swatches` для быстрой визуальной проверки и сгенерируйте
   calibration candidate;
4. откройте его в Snapmaker Orca, проверьте и slice;
5. напечатайте chart точным CMY+T4 loadout;
6. измерьте каждый нужный swatch или сравните его при контролируемом освещении;
7. внесите recipe, measured `#RRGGBB`, дату, метод и подтверждение физического swatch;
8. пересчитайте основной проект.

Новые candidates используют компактные плашки 18×16×0,64 мм с маркировкой
общей высотой до 0,96 мм. `Quick` печатает четыре solid и шесть пар 1:1;
`Full` дополнительно покрывает обе пропорции 2:1 каждой пары и все равные
трёхцветные смеси. Каждый recipe stack занимает не более трёх слоёв. Старые
18-swatch candidates остаются валидными со своим исходным manifest и geometry
preset.

Instrument Lab/sRGB даёт более надёжные данные; visual comparison сохраняется как низкоуверенное свидетельство. Legacy/nominal записи видимы, но не используются как measured calibration.

Black или White можно применять как прямой solid T4 без mix calibration. Физически точный смешанный рецепт с ними требует измерения в этом точном контексте. Без него результат остаётся nominal approximation и требует явного одобрения.

## 11. Если конвертация заблокирована

### Экспериментальная оптимизация ориентации

В desktop-программе эта возможность выключена по умолчанию и выполняется после
обычного создания файлов проекта:

1. создайте итоговые файлы через стандартный conversion flow;
2. на экране **Conversion complete** включите **Enable optional support-aware
   optimization after conversion**;
3. программа прочитает фактические платы из каждого созданного 3MF;
4. флажками выберите платы, которые нужно оптимизировать;
5. выберите режим **Bed adhesion**:
   - **Standard** сохраняет Auto Brim;
   - **Reliable** (по умолчанию) задаёт внешний brim по максимальному риску
     детали и замедляет первые три слоя;
   - **Maximum** добавляет двухслойный raft, 18-мм внешний brim и четыре
     замедленных начальных слоя;
6. нажмите **Optimize selected plates**;
7. для каждого выбранного итогового файла укажите путь отдельной
   `-support-optimized.3mf` копии.

После успешной оптимизации созданная копия заменяет соответствующий исходный
3MF в основном списке файлов для открытия в слайсере. Исходный опубликованный
3MF не удаляется: он доступен в сворачиваемом дополнительном списке
`original non-optimized files` для сравнения или ручной проверки прежней
раскладки. Программа регистрирует размер и SHA-256 оптимизированной копии,
поэтому быстрые действия откажутся открывать файл, если он был изменён после
оптимизации.

Каждый итоговый 3MF оптимизируется независимо. Если для одной из выбранных плат
не удаётся доказать безопасную раскладку с выбранным process envelope,
успешно созданные копии остальных файлов сохраняются и используются дальше.
Для невместившейся платы программа оставляет исходный проверенный 3MF в основном
списке и показывает статус о сохранении исходной раскладки, а не общую ошибку всего
этапа. В обычном случае используется консервативный envelope 18 мм. Для режима
Reliable с выделенным PVA применяется точный 5-мм внешний brim; это отдельный
проверяемый контракт, а не произвольное ослабление зазоров.

Если после этого открыть `Print Run`, тот же оптимизированный 3MF используется
в основном списке и в карточке текущей target plate. Исходный опубликованный
файл остаётся в сворачиваемом разделе `Original non-optimized files`. Прогресс
запуска привязывается к checksum фактически выбранной оптимизированной копии,
но проверка manifest и полноты исходного опубликованного bundle сохраняется.

Опубликованный комплект, его manifest и checksums не изменяются. Перед расчётом
программа повторно проверяет размер и SHA-256 созданного файла. Оптимизированную
копию нельзя сохранить внутрь опубликованного bundle: это защищает уже
проверенный результат. Если оптимизация не подходит, используйте обычный
итоговый 3MF, который был создан на первом этапе.

При повторной упаковке программа обычно резервирует вокруг каждой модели по
18 мм под поддержки, Auto Brim и другие траектории первого слоя. Для Reliable
с выделенным PVA резервируется фактически записанный внешний brim 5 мм. Между
геометрией соседних моделей тогда остаётся не менее 12 мм: два отдельных
5-мм brim и ещё 2 мм чистого зазора. Контуры brim не накладываются друг на
друга, потому что Snapmaker Orca не объединяет такие пересечения безопасно.
Если на столе помещаются сами модели, но не помещаются выбранные защитные
области, оптимизация отклонит раскладку.

Для каждой выбранной ориентации рассчитывается adhesion risk 0–100 по площади
контакта со столом, высоте, отношению высоты к корню площади контакта и числу
малых изолированных overhang-компонент. Результат содержит уровни `low`,
`moderate`, `high` или `critical` и рекомендуемую ширину brim 5/8/12/18 мм.
Режим Reliable без PVA применяет максимальную рекомендацию платы. С выделенным
PVA он использует фиксированный внешний brim 5 мм и тот же 5-мм packing
envelope, сохраняя отдельные траектории каждой детали.

Если выделенный PVA действительно назначен поддержкам, оптимизатор ищет более
низкую укладку, но отбрасывает вариант при росте оценочного объёма поддержек
более чем примерно на 35% относительно исходной ориентации либо при появлении
нескольких новых малых support-островков. Поэтому деталь укладывается лёжа
только когда это не превращает почти всю нижнюю поверхность в поддержку и не
создаёт резкий рост смен инструментов.

В оптимизированной U1-копии `print_settings_id` получает отдельное versioned имя
`U1 Planner ... v2`. Полный process остаётся внутри project 3MF; файлы системных
preset Snapmaker не изменяются и не перезаписываются. Выбор другого process в
Orca после открытия считается ручным изменением и требует повторной проверки
brim, raft, поддержек, prime tower и коллизий.

Если поддержки включены, профиль v2 дополнительно задаёт для Snapmaker U1
`tree(auto)` со стилем `tree_hybrid`, выключает
`support_on_build_plate_only`, создаёт три верхних interface-слоя (четыре в
Maximum) с шагом 0,2 мм и шаблоном `rectilinear_interlaced`, включает две
стенки дерева и ограничивает скорость support до 100 мм/с. Для обычной
поддержки interface печатается со скоростью 50 мм/с и верхним Z-зазором в один
слой. Для PVA interface скорость ограничена 30 мм/с, верхний и нижний Z-зазоры
равны нулю, чтобы растворимый слой действительно касался модели. Благодаря отключённому ограничению
build-plate-only ветви при необходимости могут начинаться на уже напечатанной
части модели, а не оставлять поддерживаемый участок без интерфейса.

Перед отправкой задания всё равно откройте Preview в слайсере и в режиме
`Line Type` убедитесь, что под первыми нависающими слоями каждой детали есть
непрерывный `Support interface`. Эта визуальная проверка зависит от результата
нарезки и не может быть гарантирована одним только содержимым project 3MF.

Если позднее загрузить такую оптимизированную копию в программу как новый
проект, сохранённый режим Standard, Reliable или Maximum будет выбран в блоке
оптимизации автоматически. Программа проверяет фактические brim, raft и
first-layer параметры, поэтому одного имени профиля недостаточно. Если профиль
U1 Planner был вручную изменён в Orca, он будет показан как modified/custom, а
форма предложит Reliable как безопасное исходное значение перед созданием
новой нормализованной копии. Обычные сторонние профили Orca не переименовываются
и не распознаются ошибочно как профили U1 Planner.

Для отдельного printable object доступна CLI-проверка ориентации. Сначала
получите отчёт без изменения файла:

```sh
target/debug/u1-converter optimize-orientation project.3mf --object-id 122
```

Чтобы создать отдельную ориентированную копию, укажите новый путь назначения:

```sh
target/debug/u1-converter apply-optimized-orientation \
  project.3mf project-oriented.3mf --object-id 122
```

Команда не перезаписывает существующий файл и не изменяет исходный 3MF. После
создания копии откройте её в Snapmaker Orca, проверьте косметически важные
поверхности, поддержку, устойчивость и заново выполните packing. Эксперимент
не является автоматическим разрешением production conversion.

Для явной оптимизации всех printable instances одной платы используйте:

```sh
target/debug/u1-converter optimize-plate-orientations \
  project.3mf --plate-id 4

target/debug/u1-converter apply-optimized-plate-orientations \
  project.3mf project-plate-oriented.3mf --plate-id 4 \
  --adhesion-mode reliable
```

Этот режим всегда выключен по умолчанию: обычный анализ, планирование и
конвертация не меняют ориентации. Plate-level команда сначала выбирает для
каждой детали только Pareto-безопасный вариант, который не ухудшает score,
оценочный объём поддержек и число малых support-островков. Затем выполняется
один packing-проход. Если он не проходит, не более 50 локальных попыток меняют
кандидаты только у не поместившейся, наиболее крупной либо высокой детали.
Если безопасная раскладка не найдена, выходной файл не публикуется.

Проверьте по порядку:

1. все используемые катушки имеют **Available now**;
2. HEX имеет формат `#RRGGBB`;
3. после изменений выполнен Recalculate/Validate;
4. все Direct mappings назначены;
5. many-to-one действительно использует одну и ту же катушку;
6. material substitution подтверждён отдельно;
7. для A1 mini результат содержит одну физическую катушку и проходит 180 мм packing;
8. установлены точные квалифицированные версии Orca/Bambu Studio;
9. все обязательные warnings/approvals подтверждены;
10. выбранная output directory существует, а итоговой bundle-папки ещё нет.

Если сохранённый Print Run восстанавливается после перезапуска, frontend-запись
используется только как недоверенная подсказка, где искать bundle. Право на
восстановление даёт отдельная backend-private запись из application-data
`publication-receipts-v1`. Она связывает версию сборки, канонический путь,
размер и SHA-256 исходника, fingerprint плана, hash canonical preflight,
выходной путь и identity каталога, а также пути, размеры и SHA-256 всех 3MF и
metadata-файлов.

Backend повторно проверяет source, план, output identity, каждый project 3MF,
manifest, report, пошаговую инструкцию и checksums. Восстановление работает fail-closed: отсутствие,
устаревание или несовпадение private receipt, перенос/подмена каталога либо
изменение любого файла блокирует Print Run. Поскольку converter никогда не
перезаписывает существующий output path, для повторной конвертации выберите
другую родительскую папку либо сначала переместите/удалите старый недоверенный
bundle.

Сам checksummed bundle можно скопировать и открыть в целевом слайсере, но
автоматическое восстановление Print Run намеренно привязано к исходному месту
публикации и identity каталога.
